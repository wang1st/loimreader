# ADR-0001：C17 模块化单体与渐进式替换 Qt

## 状态

已接受

## 背景

现有程序把图片处理、分页、网络、鉴权、更新和 Qt Widgets 混在同一批 C++ 类中，无法独立测试核心逻辑。当前打包依赖 Qt 6，旧工程还保留 Poppler-Qt5 头文件和静态 Qt 构建说明，商业分发需要持续处理 LGPL/GPL 或商业许可义务。

## 决策

新版本采用 C17 模块化单体。无 UI 的 `loim_core` 是唯一业务真相；Qt 工程仅由 `LOIM_BUILD_LEGACY_QT=ON` 显式启用，在迁移验收完成前不删除。

## 后果

### 正面

- 核心算法不依赖 GUI，可在六个目标上快速构建和测试。
- 显式所有权和错误码降低异常跨 ABI、隐式共享状态和内存峰值风险。
- 可逐功能迁移，现有可用版本不会因一次性重写而中断。

### 负面

- 迁移期同时维护新旧入口。
- C 缺少 RAII，需要严格的清理路径和动态分析工具。
- 原 Qt 功能不能自动复用，需要重新实现平台适配。

### 中性

- 3.0 是架构大版本；2.x 只接受必要维护。

## 备选方案

- **继续 Qt/C++**：开发成本最低，但不能满足降低 Qt 许可依赖的目标。
- **一次性重写并删除旧代码**：仓库更干净，但回归和延期风险不可接受。
- **微服务/插件架构**：桌面单用户工作流没有独立部署或扩缩容需求，运维和 ABI 成本过高。
