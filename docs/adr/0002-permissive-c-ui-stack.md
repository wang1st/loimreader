# ADR-0002：SDL3 自绘应用外壳与可选 Nuklear 控件

## 状态

已接受，应用外壳已完成视觉验证

## 背景

应用需要 Windows、Linux、macOS 的 amd64/arm64 支持、多文件选择、拖放、缩放画布和自定义分割交互。主发行物希望避免 Qt 商业许可或 LGPLv3 合规的不确定性，并以 C 为主。

## 决策

使用 zlib 许可的 SDL3 负责窗口、输入、文件对话框、拖放和渲染。为了尽可能复刻 2.x 的工具栏、双画布、分隔条与分页拖拽体验，应用外壳直接用 SDL3 绘制，并保持无状态的命中区域；业务状态仍只存在于应用模型中。

登录、偏好设置等表单在迁移到生产实现时可以引入固定版本的 Nuklear（MIT/公有领域双许可），但它不是当前应用外壳的必需依赖。只有实际进入构建图的依赖才写入 SBOM。原生打印、钥匙串和安装更新通过窄平台适配器实现。

## 后果

### 正面

- 主栈为 C 且允许闭源商业静态链接。
- SDL3 官方支持三个目标操作系统，渲染和输入行为一致。
- 自定义长图画布和分割线不会受传统控件树限制。

### 负面

- 即时模式 UI 的无障碍、输入法和原生观感需要额外工程投入。
- 打印和安全存储仍需平台代码；macOS 适配文件可能使用 Objective-C 语法，但不得进入核心。
- 自绘外壳需要维护命中测试、键盘导航和高 DPI 布局代码。

### 中性

- UI 外观由项目自行控制，不再继承 Qt 样式。

## 备选方案

- **libui-ng**：MIT 且原生控件，但项目官方仍标记为 mid-alpha，不作为商业主框架。
- **GTK4**：C API 成熟，但 LGPL 和跨平台打包体积不符合本次许可与原生体验目标。
- **三套原生 UI**：体验最好，但团队需维护 Win32、AppKit 和 GTK 三套功能，交付成本过高。
- **SDL3 自绘全部控件**：用于画布与工具栏，但不用于密码输入等复杂表单，避免重复建设文本编辑和输入法。
