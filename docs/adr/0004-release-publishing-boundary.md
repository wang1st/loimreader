# ADR-0004：GitHub Release 后通过受鉴权 API 登记版本

## 状态

已接受；安装包镜像与下载部分由 ADR-0005 扩展

## 背景

ctdy123.com 与 z-pulse.cn 共用 ECS。若桌面软件发布工作流直接 SSH 登录服务器、覆盖目录或重启共享服务，一次误操作可能同时影响两个站点。现有 ctdy123 代码已有 OSS 版本服务，但版本写接口缺少发布专用鉴权。

## 决策

桌面发布流水线不接触 ECS。六个产物全部完成后，GitHub 创建 Release，并使用环境级 `CTDY123_RELEASE_TOKEN` 调用发布专用 HTTPS API。网站验证 Token、版本格式、六个包、SHA-256 和幂等键，再原子更新 OSS 清单并刷新自身缓存。

## 后果

### 正面

- 软件发布与两站点的进程、Nginx 和目录完全解耦。
- Token 可单独轮换和审计，不暴露 root 密码。
- 网站登记失败时旧版本清单继续有效。

### 负面

- 需要先部署一次网站端安全接口。
- GitHub Release 与网站登记是两个阶段，需要补偿重试。

### 中性

- OSS 继续承载大文件，ctdy123.com 只管理可信元数据。

## 备选方案

- **GitHub Actions SSH 到 ECS**：拒绝；权限过大且共享主机爆炸半径不可接受。
- **工作流直接写 OSS version.json**：可用但绕过网站验证、审计和缓存刷新。
- **网站定时轮询 GitHub Release**：权限最少，但版本上线延迟且仍需签名验证逻辑。
