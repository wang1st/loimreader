# LoimReader 3.0 系统设计

## 1. 需求摘要

### 功能需求

- 一次导入多个 PNG、JPEG、GIF、BMP 文件，保留用户选择顺序并允许后续重排。
- 将不同宽度图片映射到同一虚拟长画布，分页时不创建一张巨型中间位图。
- A4 分页优先落在图片边界、空白行或人工指定位置，并允许用户拖动微调。
- 提供预览、PDF 导出、打印、登录鉴权、自动更新和中英文界面。
- Windows、Linux、macOS 均提供 amd64 和 arm64 产物。
- GitHub 标签发布自动生成 MSI、DEB、DMG、校验和、签名清单和 Release。
- 发布成功后，通过 ctdy123.com 的受鉴权版本接口上传到私有 OSS 并登记版本；不通过 SSH 改写共享 ECS。

### 非功能需求

- **许可**：新发行二进制不得链接 Qt、Poppler-Qt 或 GPL-only 组件；每个依赖必须进入 SBOM 和第三方声明。
- **内存**：分页规划开销与图片数量和切分提示数量线性相关；不与总像素量线性增长。
- **性能**：100 张图片的分页规划在普通桌面 CPU 上目标低于 100 ms；解码和缩略图生成在工作线程执行。
- **可靠性**：无效图片只影响对应导入项；发布清单必须在全部六个产物上传并校验后才切换为最新版本。
- **安全**：版本发布使用最小权限 API Token、常量时间比较、幂等版本号和 SHA-256；工作流不持有 ECS root 凭据。
- **可维护性**：C17、无隐式全局状态、显式所有权、错误码返回、严格警告视为错误、核心算法可无 UI 测试。
- **兼容性**：路径在内部统一为 UTF-8；平台适配层负责 Windows UTF-16、macOS 安全范围和 Linux 桌面门户转换。

## 3. 组件边界

### `loim_core`

- 只依赖 C17 标准库。
- 拥有源图片元数据、切分提示、虚拟坐标和页面切片。
- 不拥有窗口、网络、打印机或用户会话。
- 当前已实现 PNG/JPEG/GIF/BMP 元信息探测、批量源文档、RGBA 空白行分析和分页规划。

### 图片编解码层

- 计划使用 SDL3_image 的固定版本；依赖采用静态构建并生成 SBOM。
- 原图保持独立，缩略图按需缓存；分页渲染一次只解码当前页涉及的源区域。
- 超大图片解码器不支持区域读取时，使用有上限的代理图生成切分提示。

### UI 层

- SDL3 提供窗口、输入、拖放、渲染和原生多文件选择回调。
- 工具栏、50:50 双画布、可拖动中缝和分页线直接复刻 2.x 的灰白视觉体系；画布不持有业务模型。
- 登录、设置等复杂表单可由 Nuklear 承载，但只有实际引入构建后才作为发行依赖。
- 所有 UI 操作转换成应用命令；撤销/重做不直接操作像素。

### PDF 与打印

- PDF 导出计划使用 Apache-2.0 的 PDFio。
- 打印接口为 `loim_platform_print_pdf()`：Windows、macOS、Linux 分别实现，核心只传临时 PDF 路径。
- 平台适配失败时保留已导出的 PDF，并提示用户使用系统查看器打印。

### 更新与发布

- 客户端只信任嵌入公钥签名的版本清单，并校验包的 SHA-256。
- GitHub Actions 构建六个目标，生成 SBOM、SHA-256、兼容 MD5 与 Ed25519 签名，再创建 GitHub Release。
- ctdy123.com 先签发短期 OSS 上传地址，再流式校验六个安装包，最后更新版本清单；它不部署网站代码，也不重启 Nginx 或 z-pulse 服务。
- 下载页和新旧客户端只持有 `ctdy123.com/download/loimreader/...` 稳定地址；私有 OSS 地址按次短期签发。
- 旧 Qt 的 `checksumMD5`、`updateUrl`、平台级 `packages` 和登录/心跳更新字段继续保留；新清单以 SHA-256 为主校验。

## 4. 数据流：批量导入与优雅切分

```text
多文件选择/拖放
      │
      ▼
格式与尺寸探测 ──失败──▶ 单项错误（其余文件继续）
      │
      ▼
按统一宽度建立虚拟坐标（不拼接像素）
      │
      ├──▶ 图片自然边界
      ├──▶ 代理图空白/低边缘行
      └──▶ 用户手工分割线
      │
      ▼
在最短/最长页约束内评分候选断点
      │
      ▼
页面切片引用 {源图片, 源区域, 页内目标区域}
      │
      ├──▶ 屏幕预览
      └──▶ PDF/打印渲染
```

边界和切分提示只是坐标，不复制原图。不同宽度源图按比例映射到统一内容宽度；图片间空隙保留为页内白色区域。分页选择使用“距理想页高的偏差 - 提示质量奖励”评分，人工断点权重最高，图片自然边界次之。

## 5. 六目标构建与产物

| 平台 | amd64 | arm64 | 建议格式 |
|---|---|---|---|
| Windows | `windows-2025` | `windows-11-arm` | MSI |
| Linux | `ubuntu-24.04` | `ubuntu-24.04-arm` | DEB |
| macOS | `macos-26-intel` | `macos-26` | DMG |

GitHub 当前已为公开和私有仓库提供上述标准 arm64 标签；私有仓库会消耗账户的 Actions 分钟额度，公开仓库按 GitHub 的公开仓库计费规则运行。发布工作流固定具体运行器标签，避免 `latest` 迁移导致不可复现构建。

## 6. 失败模式

| 失败 | 影响 | 缓解 |
|---|---|---|
| 单张图片损坏 | 该项无法导入 | 逐项验证并汇总错误，不回滚已成功项 |
| 超大图内存不足 | 当前缩略图/页面渲染失败 | 有界缓存、代理图、按页解码、保留文档模型 |
| 找不到高质量空隙 | 可能切到内容 | 回退理想页高并显示可拖动分割线 |
| 某架构构建失败 | 版本不完整 | 发布阶段要求六个构建全部成功 |
| GitHub Release 成功、网站登记失败 | 新包存在但客户端看不到 | 重试幂等 API；旧清单保持有效 |
| 安装包上传不完整或摘要不符 | 新版本不可下载 | 网站拒绝切换清单，重跑上传与登记 |
| ctdy123 API Token 泄露 | 可伪造版本登记 | 环境级 Secret、最小权限、轮换、签名清单二次校验 |
| ctdy123 服务故障 | 无法查询新版本 | OSS 清单缓存；客户端指数退避，不阻塞启动 |
| 共享 ECS 操作误伤 z-pulse.cn | 两站同时中断 | 发布链路禁止 SSH/root；网站部署使用独立用户、目录和 systemd 单元 |

## 7. 迁移顺序

1. 建立 `loim_core`、测试与六架构 CI；Qt 应用仍可通过显式开关构建。
2. SDL3 窗口与批量选择接入核心，完成预览和分割线编辑。
3. PDF 导出、平台打印、登录、更新检查迁移。
4. 六平台安装包、签名、公证、SBOM、ctdy123 镜像和自动版本登记进入灰度。
5. 功能与数据兼容验收后，停止发布 Qt 二进制；最后再移动或删除 legacy 源码。

Qt 代码在迁移期间只用于行为对照，不进入 3.0 发布产物。许可结论需要由实际发行清单和法律顾问最终确认。
